# Architecture

Within is a native macOS app built with SwiftUI and AppKit, with a regular Dock presence and a menu-bar shortcut surface. Its product modules are Dictation and Notes. Meetings is a hidden developer preview behind the `showMeetingsSpace` default, which is off unless set; with it off, nothing in the app can start meeting capture. Developer commands are separate (see [privacy](PRIVACY.md#meetings-developer-preview-hidden)).

| Component | Responsibility |
| --- | --- |
| `WithinCore` | Session, target, shortcut, clipboard-generation, model-integrity, and download-boundary policy without GUI or device I/O. It also holds per-mode `CaptureLimits`, the note and meeting records, and the meeting rules: the `MeetingLifecycle` reducer, `MeetingHealthMonitor`, the `MeetingSettle` rule and `MeetingTranscriptBuilder`, gaps, Markdown export, search and crash recovery (`MeetingExport`, `MeetingSearch`, `MeetingRecovery`), `DocumentRetention`, and reminder detection (`MeetingDetector`, `MeetingReminderState`). `MeetingCallMonitor` holds a call-end rule that the app doesn't use in this build. |
| `WithinAudioBuffer` | Preallocated C single-producer/single-consumer ring with bounded backlog, total samples, and explicit close/drain handling. |
| `AppModel` | Main-actor session transitions; session IDs reject late output and prevent overlapping capture or loss of pending words. `activeCapture` says whether dictation, a note or a meeting holds capture, so only one runs at a time; an open meeting holds it while paused too. It owns the `MeetingController` and acts as its `MeetingHost`. |
| `LocalSpeech` | Actor-owned local Parakeet inference with serial sliding-window ingress. Dictation and note recording use one session. A meeting uses the named You session, and Others too when an app's sound is included; they take turns on model work. Others loads its own model copy, because a shared instance lost words in testing. The copy stays loaded between stretches until the meeting finishes or is discarded, or the models unload, as on lock, sleep, a user switch or memory pressure. |
| `OutputMutePolicy` / `SystemOutput` | Opt-in mute while dictating. Mutes the default output device only when another app is playing and no other app is using input. Records the muted device UID so the same device is restored on stop, cancel, lock or quit, with best-effort recovery at the next launch. |
| `UpdateCheck` / `UpdateChecker` | Opt-in or explicit update checks: one ephemeral GET to this repository's GitHub releases list, restricted by `NetworkBoundary`, comparing the published `v<version>-build<n>` tag with `CFBundleVersion`. Nothing downloads or installs itself. |
| `AppAudioTap` | macOS 14.2+: a private Core Audio process tap of one app's audio processes and an aggregate device, downmixed into a bounded ring. A meeting's tap is unmuted, so the user keeps hearing the call. A tapped process leaving, a new process of the same app, or an output-device change is reported so the meeting pauses; the tap is never widened. Used by `AppAudioSource` and by developer commands; the fixture commands tap only their own `afplay` process, muted. |
| `MeetingController` / `MeetingAudioSource` | One meeting's capture on the main actor, in the hidden preview. It drives `MeetingLifecycle` and runs each stretch of capture as one task. `MicrophoneSource` uses the shared capture engine, `AppAudioSource` taps the meeting app, and the developer fixture uses `FixtureSource`. `MeetingCheckpointWriter` saves the record off the main actor, newest revision only, and never writes back a deleted meeting. |
| `MeetingStore` / `MeetingUpkeep` | One owner-only JSON file per meeting in `Meetings.noindex`, through the same `LocalDocumentStore` as notes. A new folder is excluded from backups before its first file unless `meetingBackups` is on. At launch, whatever the default says and only if the folder exists, upkeep applies the backup choice, removes staging files, saves meetings a crash left open as finished (or deletes one that holds no words, notes or title), and deletes meetings past `meetingRetention`. |
| `MeetingWatcher` / `ReminderPanel` | Opt-in Zoom reminders. While `meetingReminders` and the default are on, on macOS 14.2+, the watcher reads audio processes' bundle IDs and running flags every 2 seconds for `MeetingDetector`; it never starts, pauses or ends a meeting. `ReminderPanel` and the meeting indicator, a `MeetingCapsuleView` in a `RecordingPanel`, float without activating Within. The reminder becomes key only after a click; the indicator never does. The menu bar menu repeats their actions. |
| `ModelStore` | Explicit download, constrained redirects, bounded staging, per-file size/hash validation, and atomic installation. |
| `AccessibilityTarget` | Non-content target identities, secure-control refusal, exact target revalidation, and selected-text insertion. |
| `ShortcutManager` / `AppDelegate` | Explicit shortcut modes, app windows, lifecycle, and single-instance ownership. |

One native window has a sidebar of spaces: Dictation and Notes, and Meetings only while the hidden default is on. Notes record through the same single session, capture engine and local model as dictation (one capture at a time) with per-mode `CaptureLimits`: dictation keeps 5 minutes and a 20-second backlog; a note recording allows 3 hours with the same backlog; `CaptureLimits.meeting` gives each meeting source's ring a 3-hour stretch with the same backlog. Live note text comes from the speech actor's confirmed and still-changing transcript at most twice a second; dictation receives no partial text. `NotesStore` keeps one owner-only JSON file per note, checkpointed about every ten seconds while recording. Settings sections and Help sit in the same sidebar; setup takes over the whole window, and recovery appears in-window. Sidebar choices pass through the same dialog, shortcut-editing and practice-exit guards. Optional dictation history (`HistoryPolicy` retention, owner-only `HistoryStore` file excluded from backups) is written only after confirmed insertion or explicit Copy. Practice expands inside the Dictation space; its shortcut route requires that area to be open, the main window to be key, the app to be active and no dialog to be present. Leaving active practice asks before cancellation and rechecks the session after the alert. Navigation preserves practice and pending recovery words. Attached dialogs take priority over navigation; recovery waits for their dismissal. Closing keeps the process available; Dock reopen presents Home. The separate recording panel cannot become key or main. Navigation never starts capture. Model installation and successful verification are separate readiness states.

Custom key combinations use Carbon hotkeys; supported individual modifiers use AppKit event monitors with Accessibility for global events. Hold mode arms after 350 ms; toggle mode requires a short tap and observed release. Key, modifier, mouse-down and scroll combinations interrupt modifier gestures. The selected hardware key supplies missed-release recovery. Explicit shortcut editing unregisters dictation bindings and blocks capture. Legacy preset preferences migrate without changing the user's selected chord; downgrading to an older build restores its prior preset. Setup, Practice, and Audio settings share the same microphone picker and active-session lockout.

Diagnostic schema 5's shortcut booleans report Control, Shift and the selected trigger key. They do not describe the full custom binding or its Command/Option state; do not infer shortcut availability or all held modifiers from that snapshot. Startup milestones report cumulative milliseconds from an accepted start action through first audio observation, sampled by the 50 ms UI pulse. The clock excludes shortcut recognition and its hold guard; it does not measure when the UI was painted. Missing milestones mean that stage was not reached. Only the latest session remains in memory, with no wall-clock times, audio, text, or target/device identities. Schema 5 also carries `MeetingDiagnostic`: closed facts about the last meeting in this run, with no titles, words, notes, app names, counts, durations or times.

Capture follows an explicit action, verified model preparation, an audio tap, the bounded ring, and a serial inference consumer. In dictation, the ring bounds queued audio to 20 seconds and a session is capped at five minutes. Overflow stops capture; available text goes to review. Audio is not persisted by the app.

Stopping always stops the audio hardware, removes the tap, and closes the session's ring; the existing consumer can finish draining buffered audio. The stopped engine retains no tap or ring and can be reused for the same explicitly selected input; the system-default route is recreated. Each capture has a separate generation so delayed configuration callbacks cannot stop a later session on the same engine. Input changes, errors/cancellation, permission loss, model removal, lock/sleep, memory-pressure unloading and quit discard reuse state. No engine is prepared or started to keep the microphone warm at idle.

Meeting capture, in the hidden preview, starts only from an explicit action. Setup's Start meeting and Continue this meeting need the participant acknowledgment. The start button of a reminder, or of the sheet Start Zoom Notes… opens, is that acknowledgment for the meeting it starts. Resume asks for it again after a lock, sleep or user switch, after the app's sound went away or the output device changed, or after a pause over 15 minutes. `AppModel` refuses it while dictation, a note recording, pending dictation words, practice or a shortcut change holds capture. While a meeting is open, paused included, it refuses dictation, note recording, and model download or removal. `MeetingController` saves the record before any source starts. Each stretch claims the shared session, prepares the verified model, begins the You session and, when an app's sound is included, the Others session, then starts each source into its own ring. Both sessions' updates are applied in the order they were produced. Confirmed text joins the saved transcript as the speech session confirms it. `MeetingSettle` adds a source's still-changing tail once it stays the same for about 13 seconds of further audio, or after 15 seconds of quiet. Until then the tail is shown but not saved; a stretch that drains in full keeps its final text. A changed record starts saving within 5 seconds, off the main actor; a failed save is reported and tried again 5 seconds later. A 100 ms pulse applies `MeetingHealthMonitor`. A stall, a lost or changed source, a microphone permission change, a full backlog or a speech error ends the stretch, and so do lock, sleep and a user switch. Both sources stop before anything awaits; the sessions drain, and the stretch records why it ended, which the transcript shows as a gap. Nothing resumes on its own. A stretch that reaches three hours continues in a new one. The microphone source never keeps its stopped engine for reuse. Quit stops the sources at once, drains for up to 10 seconds and saves before quitting. Nothing pauses a meeting when a call ends in this build.

The original application, window, control, focus history, and secure-input state are checked before insertion. A failed write is uncertain and is not automatically retried. Recovery keeps words available for an explicit user action. Accessibility cannot make focus checking and writing atomic, so real target-app validation remains required.

Compatibility paste is an experimental, explicit setting. It is selected before capture only when a safe control lacks direct insertion capability. It snapshots bounded clipboard data and restores it only if no other writer changed the clipboard generation. Synthesized paste cannot confirm insertion; the result remains available for review.

## Dependencies and integrity

The checked-in FluidAudio patch disables central log sinks, adds serial bounded ingress, and surfaces individual window failures. Unused NeMo binary resolution is removed. Bootstrap pins the source revision and checks the patch; original license notices are retained.

The bundled manifest pins model revision, file sizes, and SHA-256 hashes. A staged download must match the manifest before installation. First load and loading after eviction run full verification. While models remain resident, each session validates the manifest, inventory, types, sizes, file/device identities and nanosecond modification/change metadata. Changed metadata or a proof at least five minutes old requires full hashing before capture. Full verification compares metadata before and after hashing; failures clear the proof. Nothing is persisted as a trusted cache. A five-minute background task rehashes only while speech is idle; an expired check deferred during speech runs before the next capture. Failure unloads the model and invalidates readiness. A trusted app distribution signature is necessary to authenticate the manifest for public distribution.

Changes to these boundaries need appropriate core tests and, where OS behavior is involved, observed checks from the [validation matrix](VALIDATION.md).
